## Description

> You Trusted the Technology, but Did You Check What Happened Recently?

## Analysis

The challenge is a `dynamic_docker` challenge backed by CTFd-Whale.

The metadata does not contain the challenge application's source code or
container image, so the first step is infrastructure fingerprinting rather
than assuming a conventional SQLi/XSS vulnerability.

The title strongly suggests that the intended vulnerability is related to a
recent security disclosure affecting technology trusted by the challenge
infrastructure.

Two candidates are particularly relevant:

### Candidate 1: CTFd CVE-2025-23001
CTFd 3.7.5 was affected by a Host-header injection issue. An attacker could
supply an arbitrary `Host` header and influence absolute URLs generated by
the application.

This is especially interesting for password-reset functionality because
reset URLs can be constructed using the request hostname.
CTFd addressed the problem in 3.7.6 by introducing `TRUSTED_HOSTS`.

### Candidate 2: runc Container Escape
The CTFd-Whale infrastructure uses Docker containers. Recent runc
vulnerabilities disclosed in November 2025 (CVE-2025-31133, CVE-2025-52565, CVE-2025-52881)
are another plausible interpretation if container creation or runc execution is exposed.

## Intended Reconnaissance

Run:

```bash
python3 solve.py https://<booted-instance>
```

The script:
1. Fingerprints CTFd endpoints & version disclosures.
2. Tests whether the HTTP `Host` header is trusted (CVE-2025-23001).
3. Identifies possible password-reset endpoints.
4. Checks local runtime for `runc` and `/var/run/docker.sock`.
